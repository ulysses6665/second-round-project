# 会话记录

这里保存本项目与 agent 的交流记录。日志帮助你找回讨论过的决定，也供负责人核查过程。一次会话对应一个文件，恢复后继续写入原文件，跨天也不另开。

## 日志会存成什么样

目录按建档当天命名，文件名包含时间和会话标识。完整规则见[根 AGENTS.md](../../AGENTS.md)的「会话日志的定位与命名」。

```text
.agents/sessions/YYYY-MM-DD/HH-mm-ss-<会话标识>.md
```

继续之前的会话时，应先找到对应日志。无法确认是哪份，就先询问；不能凭内容相似覆盖其他文件。

## 每轮记录什么

agent 先保存本轮项目相关的请求原话，结束前补齐可见答复。进展说明和提问也要保留，纯问答同样记录。工具操作只需留下用途和关键结果，再写明实际验证及未完成项。

具体格式见[日志模板](TEMPLATE.md)；执行顺序以[根 AGENTS.md](../../AGENTS.md)为准。这里不另列一套格式，也不要求把工具的全部原始输出复制进来。`TEMPLATE.md` 只提供格式，不记录会话，不要按日志处理。

保存前先移除敏感内容，省略处写明类别。考核原文、密钥和私人信息不能写入。

## 怎样和任务一起提交

日志需要提交，但不用每轮对话都 commit 或开一个 PR。按[项目 Git 流程](../../README.md#每个任务怎样保存进展)，在相应任务分支保存进展。只有讨论时，可以集中放在文档分支提交。

切换分支前，检查日志是否已经保留。切换后找不到本会话文件，要先确认怎样从原分支安全带回。不能新建同名空文件，假装原记录已经续写。

## 找不到日志或写入失败时

agent 应告知原因，暂停项目实施，仍可解释问题和帮助恢复记录。没有写入成功，不能只凭一句“已保存”继续工作。日志不具备防篡改保证，负责人会结合会话节选、代码说明和现场修改核查。

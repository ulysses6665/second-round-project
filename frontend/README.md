# 前端工程

你在浏览器里看到的页面，以及点击、输入后的反应，都属于前端的工作。这里用来放前端工程，当前还没有初始化。项目流程和 Git 规范先读[根 README](../README.md)。

## 先选一套能够解释的方案

推荐 Vue 3 + Vite，不强制使用。Vue 用来组织页面组件和交互，Vite 提供开发与构建工具。如果采用这套方案，先了解 Node.js 和包管理器的用途，再按官方文档准备兼容的环境。Node.js 在这里运行工程工具；包管理器用来安装和管理依赖。

JavaScript 和 TypeScript 都可以。TypeScript 额外提供类型检查能力，也需要学习相应写法。可以先请 agent 解释区别，再说明自己的选择理由。

路由用于处理页面地址和页面切换，状态管理用于组织共享数据。它们和 UI 组件库都按需要添加，不要求初始化时全部选上。选择其他前端方案也可以，但同样需要完整的工程。

工程至少要能管理依赖，提供开发启动和构建方式。页面按所选方案组织成组件或模块，依赖清单和必要构建配置也要提交。

## 先亲自把页面打开

阅读所选方案的官方入门说明，确认环境要求，再亲自执行初始化。可以使用官方脚手架。agent 可以解释选项和错误，不能代替你创建工程。

本目录已有 `README.md`、`AGENTS.md` 和 `.gitignore`。生成前确认目标位置，保留这些说明和规则，让工程文件直接位于本目录。

第一次启动后，打开实际页面，确认浏览器中显示了什么。再打开开发者工具，在控制台查看错误，在网络面板观察一次实际请求。接入后端后，核对请求地址、返回状态和内容，不只看页面有没有变化。

开发启动与构建是两种操作。开发启动用于本地调试，构建会生成用于发布的产物。首次启动、构建和浏览器请求在学到相应操作时分别亲自完成，不作为 Java、SQL 或其他学习任务的统一前置条件。

## 哪些文件要提交

提交源代码、依赖清单和所用包管理器的锁文件。锁文件记录具体的依赖解析结果，方便其他人安装相同依赖。必要配置也要保留，依赖安装目录和构建产物不提交。

使用与当前工程一致的包管理器。如果更换，说明理由，并处理不再使用的锁文件，避免留下几套互相冲突的安装依据。

需要环境变量时，提供示例文件并说明用途，真实值留在本地。前端运行在使用者的浏览器里，可被浏览器读取的配置不能保密。后端密码、令牌和私钥不能放在前端。

## 工程建立后补全这份说明

保留本说明作为入口，随后写入实际使用的技术和版本。给出安装依赖、开发启动及构建命令，说明应在哪个目录执行。若有检查或测试命令，也一并写清。

说明后端地址怎样配置，以及如何验证页面确实发出了请求。提供别人可以照做的检查步骤。使用 TypeScript 时，把类型检查方式写明，不要默认构建工具已经检查了类型。

页面变化在 PR 中附实际截图。没有检查的浏览器行为如实写明，不能用示例截图代替运行结果。

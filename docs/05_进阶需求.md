# 05 进阶需求

基础完成后再选做，不要求六周内全部实现。开始前保留当前版本，每次改完重跑旧流程。

## E1：大额申请二级审批

原始申请金额超过 500 元时，老师批准后还需财务复核；恰好 500 元不需要。

- 申请 600 元，即使老师只批准 400 元，仍需二级。
- 增加“待二级审批”状态 PENDING_L2；财务只确认或拒绝，不再改金额。
- 一级减额立即释放差额，二级通过不改变经费；拒绝或取消释放剩余冻结。
- 两级审批人不同，且都不能审批本人申请。无合法审批路径时提交失败，不冻结。
- 新规则启用后，已提交申请保留原路径；旧草稿新提交采用新规则。

想一想：原始金额、批准金额和提交时的审批路径，为什么都要保留？

## E2：操作记录、重试与并发

成功操作记录操作人、时间、动作、前后状态与原因，并与单据、经费一起成功或失败。

需要处理：

- 重复点击或响应丢失后重试，不重复冻结、释放或结算。
- 两张申请争抢只够一张的预算，恰好一张成功。
- 同一审批被同时处理，最多一次生效。
- 取消与结算同时发生，只形成一条合法状态路径。

如果使用幂等键，按“登录用户 + 动作 + 键”识别请求：同键同内容返回原成功结果，换内容报冲突。结果重启后仍有效，重试仍校验权限。JSON 字段顺序不同不算内容不同；校验失败不产生成功记录或部分副作用。

想一想：用户看到请求失败，业务是否可能已经成功？怎样证明你的处理有效？

## E3：多明细与分类预算

增加设备、耗材、差旅分类，每张申请有多条明细。

- 总预算和所有相关分类都要够用；同分类明细先汇总。
- 任一分类不足，整张申请失败，不留下部分冻结。
- 分类额度是独立上限，合计不必等于总预算，不能自动互相调拨。
- 每个分类都满足“额度 = 可用 + 冻结 + 已使用”，各项非负；本阶段不调额度。
- 项目冻结、已使用分别等于所有分类对应金额之和，但可用不必相加一致。

批准与结算按明细填写，不能只给一个总额再随意分配：

| 分类 | 申请 | 批准 | 结算 |
|---|---:|---:|---:|
| 设备 | 600 | 450 | 430 |
| 耗材 | 400 | 350 | 320 |

每条明细满足“结算不超过批准，批准不超过申请”，不能挪用其他明细余额。单条可批准零元，但批准总额必须大于零；全部不同意应拒绝。提交后不能换分类。

升级时保留旧数据：

- 用“历史未分类”承接旧申请的冻结与已使用，额度等于升级时项目总预算，可用按等式计算。
- 旧申请继续办理；新申请不能选历史分类，旧草稿提交前补有效分类。
- 不重做旧冻结或结算，保留状态、金额与记录，分类从升级时的期初余额开始核对即可。

想一想：怎样证明多分类操作失败后没有残留，以及升级前后总经费没有变化？

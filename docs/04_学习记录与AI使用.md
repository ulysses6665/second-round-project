# 04 学习记录与 AI 使用

## 完成一小步，就提交一次

写出成员类、建好成员表、完成第一个接口、修复一个错误，都可以成为一次 commit。

不要求每次都能运行完整网站，但要说明本次能运行或检查什么。及时保留真实过程，不凑提交数量，也不要最后一次性导入几周成果。

一段可能的记录：

    docs: 写下需求理解和学习计划
    feat: 添加成员类和控制台示例
    db: 添加成员表与查询
    feat: 从 MySQL 读取成员
    feat: 实现提交和经费冻结
    refactor: 将业务整理到 Service
    feat: 添加提交接口与 Vue 表单
    fix: 修复取消时重复释放经费

不用照抄，按自己的学习顺序提交。

## 提交说明写什么

写清“学了什么、做了什么、怎么检查”即可。例如：

    feat: 添加成员类和控制台示例

    学习：类、构造方法、对象实例化。
    应用：创建两个成员并打印姓名。
    验证：运行 MemberDemo，核对输出。

未完成、未理解或未运行的内容也如实说明。运行方式、当前进度放在 README 或简短学习记录中，不必重复写长报告。

## AI 可以怎样帮你

可以请 AI 解释概念、协助当前小功能、解读报错、检查代码。拿到结果后，自己运行、修改，并尝试解释。

不理解的内容先标为待学，没运行的内容不要写成“已验证”。

使用 AI 的提交保留你的 Git author，并追加贡献说明：

    AI-Assisted-By: 实际工具名称
    AI-Contribution: 生成成员类初稿；本人修改字段与示例
    Human-Verified: 运行示例并核对输出，能解释字段用途

这是本项目的记录格式，不是自动认证。没用 AI 不必填写；只解释了报错，也如实写清。模型名称能确认再填，不需要编造 AI 邮箱或保留全部聊天。

课程代码、示例或他人帮助也要注明来源。不提交密码、真实个人数据、依赖和构建产物。

**commit 是学习记录，你还需要能解释对应修改、演示怎样运行。**

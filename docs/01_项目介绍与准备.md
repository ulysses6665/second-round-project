# 01 项目介绍与准备

## 这个系统解决什么问题

科研团队有一笔项目经费，成员想购买设备或材料，需要先申请，再由老师批准。采购结束后，财务登记实际花费。

系统要记清：谁申请了什么、批准了多少钱、实际花了多少，以及还剩多少经费。

| 使用者 | 主要操作 |
|---|---|
| 项目成员 | 填申请、看进度、取消自己的申请 |
| 项目老师 | 批准、减额批准或拒绝 |
| 财务 | 登记实际花费 |
| 管理员 | 准备项目、账号和角色 |

一个人可以参加多个项目，每张申请只属于一个项目。本项目不连接银行，不进行真实支付。

## 先认识三个金额

- **可用：**还能留给新申请的钱。
- **冻结：**已经留给申请、但还没结算的钱。
- **已使用：**财务登记的实际花费。

冻结就是“先把钱留出来”，释放冻结就是“把不再需要的钱恢复可用”。具体例子见[基础需求](02_基础业务需求.md)。

## 今天先做什么

先读需求，再新建 `docs/learning-plan.md`，写四件事：

1. 我理解系统要解决什么问题。
2. 我现在会什么，还需要学什么。
3. 我准备先完成哪个小目标。
4. 我还有什么疑问。

例如：“我刚学类和对象，先写成员类，再创建两个成员。我还不懂成员与项目怎样关联，学数据库时继续研究。”

第一次设计不完整很正常，后面可以修改。你不需要先学完所有技术，也不需要第一天建好完整工程。
